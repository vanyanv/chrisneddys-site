# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- Site: the careers page has its own look now instead of sharing the privacy/terms page template. It gets a red hero band, a real photo and a proper card for the Indeed link, matching the rest of the site, and no longer calls a location a "counter" ([#72](https://github.com/vanyanv/chrisneddys-site/issues/72))

### Fixed

- Site: a mistyped or dead link no longer dead-ends. Next only ran the site's branded "not on the menu" 404 for links inside the site itself — a URL that matched no route at all (an old bookmark, a typo, a broken external link) fell through to the framework's own bare, unstyled 404 with no header and no way back. There's now a proper one for that case too ([#70](https://github.com/vanyanv/chrisneddys-site/issues/70))
- Site: you can now skip past the header straight to the page content with a keyboard, instead of tabbing through the full nav on every single page. The contact page also names how to report an accessibility problem ([#71](https://github.com/vanyanv/chrisneddys-site/issues/71))

### Added

- Site: small monster mascot illustrations, matching the murals painted on the Hollywood location's own walls, added across the home page, menu, shop, locations, 404, bag, checkout, order confirmation, footer and careers page. Nothing existing was resized or recolored to make room — the mascots are layered on top or beside what was already there. The one exception is the browser-tab icon and the site's default share-link preview, which now show the mascot instead of the old wordmark image ([#74](https://github.com/vanyanv/chrisneddys-site/issues/74))
- Site: a careers page. `/careers/` pitches the business and links straight to the Indeed company page for open roles, pay and how to apply, instead of copying listings here where they'd go stale. Linked from the site footer ([#68](https://github.com/vanyanv/chrisneddys-site/issues/68))
- Shop: a product you add now arrives with its search-engine copy already written. The admin's "Search engines" panel gains a page title, keywords, a share picture and that picture's alt text alongside the meta description that was already there, and all five are yours to edit or leave alone. Leaving one empty is not a gap: anything you have not written is worked out from the product itself, so a product is never live without a title or a snippet. Where an OpenAI API key is set (`OPENAI_API_KEY`, see DEPLOY.md), the five are written properly for you the moment the product is created, and a "Write with AI" button in the same panel rewrites them whenever you want — it never overwrites words you typed yourself unless you ask it to. The share picture is drawn from the product now, so a new product has one without anyone running a script and committing a file first; point the field at your own card when you have made one ([#64](https://github.com/vanyanv/chrisneddys-site/issues/64))
- Shop: Google Analytics finally sees the whole shop. It recorded browsing a product, adding to the bag, opening the bag and starting checkout, but never the sale itself — so the funnel stopped one step short of the only step that makes money. Completed purchases now report their order number, their value and what was in them, once per order even if the page is refreshed. Browsing the shop, tapping a product out of the grid and taking something back out of the bag are recorded too ([#64](https://github.com/vanyanv/chrisneddys-site/issues/64))
- Admin: you can sign in with a passkey — Face ID, Windows Hello, a fingerprint reader or a hardware key — instead of typing a password. Set one up from Settings on any device you sign in from, name it so you can tell them apart later, and add or remove them whenever you like. Your password does not go away and does not stop working: a passkey is a second way in, never a replacement, so losing the phone you set one up on costs you the convenience and nothing else. A failed passkey attempt counts towards the same cool-down a mistyped password does, and says the same thing back, so neither one can be used to work out whether an address has an account ([#51](https://github.com/vanyanv/chrisneddys-site/issues/51))
- Shop: the shop can be paused. A toggle in Settings stops it taking orders without unpublishing anything — every product page stays up and every link still works, only the buy button changes, and you can leave a short note ("Back Thursday") that customers see in its place. Checkout refuses while paused, so nothing slips through from a tab left open before you closed. This is a different thing from the shop not being set up yet, which still reads the way it always did ([#43](https://github.com/vanyanv/chrisneddys-site/issues/43))
- Admin: refunding an order can put its number back in the run. Until now a refund quietly kept the number marked sold forever, so a run of fifty silently became a run of forty-nine and nothing on any screen said so. The refund panel now shows the actual number and asks — left off by default, because a refund does not always mean the hat is coming back, or coming back sellable. You can also note why you refunded, which is kept with the order and never shown to the customer; when a number does go back, the customer's refund email says so ([#42](https://github.com/vanyanv/chrisneddys-site/issues/42))
- Admin: the bits of the design that were drawn and never built. The order page shows where this order's number sits in the run, how many times the customer has ordered and what they have spent, and a button to copy their address. Settings gets a "Ships within" line and shows you the exact sentence customers will read. The run board counts every hold down live and turns one red in its last minute, with a bar beside it draining as the window runs out. A customer's city shows on their page, and a sold-out product page now offers the rest of the shop instead of stopping dead ([#50](https://github.com/vanyanv/chrisneddys-site/issues/50))

### Changed

- Site: tapping between pages is instant again, without the cost that made it worth giving up. Pages used to fetch each other in the background while the page you were actually looking at was still arriving, which is why that was turned off. Now the six pages in the top bar are fetched quietly once your page has finished and the phone has nothing else to do — so opening one is immediate again, and nothing competes with the page in front of you to make it so. Skipped entirely if your phone is in data-saver mode or on a very slow connection ([#65](https://github.com/vanyanv/chrisneddys-site/issues/65))
- Site: pages no longer quietly download the rest of the site in the background. Every link on a page used to fetch that whole page ahead of time, the moment the link scrolled into view — so landing on the menu and reading to the bottom pulled half a megabyte of pages nobody had asked for, on top of the menu itself. That is off now. The cost is that tapping through to another page takes about a tenth of a second longer on a normal phone connection, where before it was instant; the saving is 344 KB on the home page and 518 KB on the menu, every visit ([#63](https://github.com/vanyanv/chrisneddys-site/issues/63))
- Site: one analytics tool instead of two. Every page used to load Google Analytics and Plausible side by side, reporting the same page views and the same named events twice over — one of them into an account nobody reads. Plausible is gone and Google Analytics stays, so the numbers you already look at are unchanged and there is one less thing for a phone to download before the page settles. Outbound clicks are still counted: Google Analytics measures them itself, and the site's own order and delivery events additionally say which part of the page the tap came from ([#57](https://github.com/vanyanv/chrisneddys-site/issues/57))
- Every page loaded the CSS for every other page. The stylesheet inlined into each storefront page was the same 116 KB on all of them, so opening the menu meant downloading the contact form, the story page's split, the shop's drop grid, the order tracker and the legal pages first — a browser cannot draw anything until it has read all of it. Each page now carries only the design system plus its own, between 21% and 30% less to read before the page appears. Nothing looks any different ([#58](https://github.com/vanyanv/chrisneddys-site/issues/58))
- Customers: the emails say the thing worth opening for in the subject line. A receipt now reads "number 35 of 50 is yours" rather than a bare order number, and a shipping notice names the carrier. Replies go to your support address instead of nowhere, so the line telling customers a reply reaches a person is now true ([#47](https://github.com/vanyanv/chrisneddys-site/issues/47))
- Admin: the packing slip says which number of how many. It printed a bare "35" where the certificate says 35 of 50 — the run total was never carried onto the order, so it could not be printed. It also no longer prints an internal SKU on a sheet that goes in the box, and it carries your returns policy ([#48](https://github.com/vanyanv/chrisneddys-site/issues/48))
- Admin: a password reset link now lasts 30 minutes rather than an hour. The screen already said how long a link lasts, but the number it said was the one the auth library happened to default to, not the one the design asked for — and nothing tied the sentence to the actual setting, so either could have been changed without the other. Both now read the same value ([#44](https://github.com/vanyanv/chrisneddys-site/issues/44))
- Admin: sign-in, forgot-password and reset-password finally look like the rest of the admin. They are full pages now rather than a small box on an empty screen. Sign in warns you how many tries are left before a cool-down, instead of only speaking up once you are already locked out. Forgot-password can send the link again, says how long it lasts, and explains that it will never say whether an address has an account. Setting a new password shows how strong it is, what it still needs, and warns that it signs out every other device — which it always did, without telling you ([#44](https://github.com/vanyanv/chrisneddys-site/issues/44))
- Admin: two warnings that used to arrive too late now arrive in time. The run size says it locks the moment the first number sells while the field can still be changed, rather than once it is already read-only. A draft lists what it still needs before it can go live, next to the button, instead of refusing after you click ([#45](https://github.com/vanyanv/chrisneddys-site/issues/45))
- Shop: the order status page gives the answer the room. Once you look an order up, the result sits beside the form instead of below it, leads with the order number and a one-word state you can scan, names what you bought properly, and draws the three steps as one connected track rather than three loose dots ([#41](https://github.com/vanyanv/chrisneddys-site/issues/41))

### Fixed

- Shop: sharing a product link previewed as a broken image. The picture a link preview uses was a file somebody had to make by hand and drop into the site, so it existed for the one product that shipped with the shop and for nothing added since — every product created in the admin pointed at a picture that was not there. A product with no name of its own on the page also put an empty title and an empty share caption into search results, which is what the admin creates before you fill it in. Both now read the name the shop actually shows. The order-status page has also stopped asking to be indexed: it is a lookup form with nothing in it worth finding in a search ([#64](https://github.com/vanyanv/chrisneddys-site/issues/64))
- Shop: clicking Buy no longer makes one customer wait for everybody else's abandoned baskets to be cleared up. When a hold on a number runs out it has to be put back before the next person can buy it, and that tidying was being done one basket at a time, by whoever happened to click next — so the more baskets had lapsed, the longer that person waited. They lapse in bunches half an hour after a drop, which is exactly when the next person is trying to buy. It is now done in one go: measured locally, clearing forty lapsed holds went from 185ms to 6ms, and clearing one is unchanged ([#61](https://github.com/vanyanv/chrisneddys-site/issues/61))
- Shop: the shop and product pages no longer wait on the database to draw themselves. Every page on the site read your store settings twice before it could render — once for the header and once for the page — and that read was the one read in the whole site with no cache on it, so it happened on every single render even when everything else on the page was already cached. It is cached now, and saving anything in Settings still shows up on the storefront immediately. The shop and product pages also stopped fetching what they need one thing at a time when they could fetch it all at once, and the shop index stopped pulling all fifty numbers of a fifty-piece run just to work out how many were left. A shop page now renders without touching the database at all ([#61](https://github.com/vanyanv/chrisneddys-site/issues/61))
- Shop: the hat page no longer downloads its whole gallery at full size on a phone. The eight little thumbnail tabs under the main photograph are drawn about the size of a postage stamp, but on any modern phone screen the browser was fetching the full-size version of every one of them — so the page arrived carrying roughly half a megabyte of photographs it then drew tiny. It now has a middle-sized cut to reach for. Measured on a phone at the density most phones actually have, the page went from 1,191 KB to 797 KB, and the photographs themselves from 688 KB to 297 KB. Nothing on the page looks any different; the main product shot is the same file it always was ([#56](https://github.com/vanyanv/chrisneddys-site/issues/56))
- Admin: inviting an owner could still intermittently fail to produce a link. The fix shipped in 0.4.0 passed the invite's outcome back through a mechanism that depends on asynchronous context surviving between two parts of the app, which it does not always do. It is now handed back directly, so the invite either works or says why ([#53](https://github.com/vanyanv/chrisneddys-site/issues/53))
- Admin: an owner you just invited appears in the list straight away, and one you remove disappears straight away. Both used to wait for the whole Settings page to re-read itself first, so on a busy moment you could send an invite, be told it worked, and still not see the person underneath it — or remove someone and watch them linger. The list now updates the moment the action comes back and reconciles with the server behind it ([#38](https://github.com/vanyanv/chrisneddys-site/issues/38))
- Admin: Settings now tells you it saved, straight away. Saving, removing an owner or sending an invite confirmed only after the whole Settings page had re-read itself behind the scenes, so the message could take many seconds to arrive or look as though it never would. The save itself was always done in milliseconds and always stuck; only the confirmation was stuck behind unrelated work ([#38](https://github.com/vanyanv/chrisneddys-site/issues/38))
- Admin: a pickup order never appeared on Today. Pickup works everywhere else — customers can choose it, orders carry it, and the emails send — but the queue that answers "what needs doing right now" was built to ignore it, so an order waiting to be prepared could sit there unseen. Pickup orders now queue alongside the ones waiting to be packed ([#49](https://github.com/vanyanv/chrisneddys-site/issues/49))
- Admin: the all-clear line only appeared once the queue was completely empty, so on a busy day nothing ever told you the shop itself was healthy. It now says which systems are fine whatever else is waiting, and names only the ones actually checked ([#50](https://github.com/vanyanv/chrisneddys-site/issues/50))
- Admin: loading screens no longer blink. A page that came back quickly still painted a full skeleton for a moment first; the skeleton now waits a beat before showing, so a fast page just appears. The top bar and the page title stay on screen throughout, so a slow page keeps its frame rather than going blank. Saving now shows a spinner while it saves, which the design always had and the code never rendered ([#46](https://github.com/vanyanv/chrisneddys-site/issues/46))
- Shop: an order never said what was in it. Every product added in the new admin recorded a blank name onto its orders, so the order status page showed an edition number with nothing beside it — and the same blank went onto the packing slip and the receipt email. Orders now record the name the shop actually shows ([#41](https://github.com/vanyanv/chrisneddys-site/issues/41))
- Admin: saving a product left the panel showing the old values. The heading kept reading "No name yet" after a name was saved, and the run kept reporting the old size — both directly under a footer saying the save had worked, and both only correcting themselves on a reload. The run count is the number you check before publishing a drop, so it mattered more than it looked ([#40](https://github.com/vanyanv/chrisneddys-site/issues/40))

## [0.4.0] - 2026-09-16

### Added

- Admin: `/admin` now opens on Today — a work queue of what actually needs doing, rather than bouncing you to the products list. It shows orders waiting to be packed oldest first, flags one that has been waiting more than a day, counts numbers held in open checkouts, and surfaces anything still unconfigured in setup. Money taken today, how many are left in the run, and what just happened sit alongside it. Every row is real data or it isn't shown ([#36](https://github.com/vanyanv/chrisneddys-site/issues/36))
- Admin: Products is now The Rack's catalogue — a card grid with a detail panel, instead of the old expanding table. Price, stock and Live/Draft change in place, and a Save bar collects a sweep of edits into one save with Undo. Adding a product opens straight onto a blank draft with no name yet, rather than asking for one up front; that empty state is honest everywhere it shows, and a draft can't go live until it actually has a name, a price, a run size and a photo. First-run and loading states are real screens now instead of a blank page. Run size, Archive, reordering, photos and duplicating all still work the same as before ([#36](https://github.com/vanyanv/chrisneddys-site/issues/36), [#28](https://github.com/vanyanv/chrisneddys-site/issues/28))
- Admin: a numbered hat now has a run board — every number in the edition on one screen, showing which have sold, which are held in a checkout right now, and which are still open. A sold number opens the order that bought it. The run size locks the moment the first number sells and says so, because by then that count is printed on a certificate in somebody's hands ([#36](https://github.com/vanyanv/chrisneddys-site/issues/36))
- Admin: Orders, the order page, Settings and the packing slip move onto the same system as Today and Products, so the whole admin looks like one thing. Orders gets search, status chips and two-line rows on phones; the order page is one surface and shows the new status right after marking an order shipped, ready, picked up or refunded; Settings gets grouped sections, a Save bar that appears only when something changed, and a Connections list. The Chris N Eddy's logo replaces the typed wordmark in the top bar, sign-in and packing slip. Refunding an order now asks first, in a panel that says plainly there is no undo, and sends the customer their confirmation ([#36](https://github.com/vanyanv/chrisneddys-site/issues/36), [#32](https://github.com/vanyanv/chrisneddys-site/issues/32))
- Admin: a Customers section — everyone who has actually bought something, what they have spent, when they first ordered, and which numbers of a run they own, with a click through to any of their orders. Somebody still part-way through a checkout is not counted as a customer, because they have not given a name or an email yet. Two different email addresses are two different customers, even if they are the same person ([#36](https://github.com/vanyanv/chrisneddys-site/issues/36))
- Admin: the admin has real screens for when things go wrong. A page that errors now shows a way back and a "try again" instead of a blank white page, with a reference code you can quote rather than a wall of technical detail. A missing page has a way out. If your session runs out while you are working, the sign-in page tells you that is what happened and that sessions last 12 hours — but only if you had actually signed in on that browser, so a first visit is never told it was signed out. Losing your connection shows a plain indicator that does not pretend to save your work, and the pages that were missing loading states now have them ([#36](https://github.com/vanyanv/chrisneddys-site/issues/36))
- Admin: sign-in is now a real account per owner, not one password shared by everyone. Each owner sets their own password and can change it from Settings; a forgotten one is reset by a link emailed to them. Settings also gets an Owners card to invite a new owner by email or remove one. Sessions now last 12 hours and can be revoked — signing out, changing a password, or removing an owner logs that device out immediately rather than leaving a 30-day token valid until it expires on its own ([#33](https://github.com/vanyanv/chrisneddys-site/issues/33))
- Shop: a numbered hat's page now shows the run itself — every number in the edition, which are gone, which are open, and which are sitting in somebody's checkout right now. A sold-out run keeps its page rather than vanishing, and the order-tracking page shows a real timeline of what has actually happened to an order instead of a bare status word ([#36](https://github.com/vanyanv/chrisneddys-site/issues/36))
- Customers: the receipt, the shipping notice and a new refund confirmation are properly designed emails now, and the receipt leads with the thing a buyer actually wants to know — which number of the run is theirs. A full refund through Stripe sends the confirmation on its own, so nobody is left wondering whether the money is coming back. Each one is sent as both a formatted and a plain-text message, so it reads correctly wherever it lands ([#36](https://github.com/vanyanv/chrisneddys-site/issues/36))
- Checkout Sessions now enable invoice creation, so Stripe generates an invoice for every order rather than only for subscriptions. Whether the customer is emailed it remains a per-environment Dashboard setting, which `DEPLOY.md` now spells out
- Development: `pnpm test:e2e` runs a Playwright suite against a production build on its own PGlite database (`PGLITE_DATA_DIR`) ([#28](https://github.com/vanyanv/chrisneddys-site/issues/28))
- Development: the e2e suite no longer fails on a slow machine. Clicking a filter chip retries if the click was swallowed mid-navigation, and assertions that wait on a save plus its re-render get a realistic ceiling instead of failing a moment before the answer arrives ([#38](https://github.com/vanyanv/chrisneddys-site/issues/38))
- Development: `pnpm release` cuts a release — it dates the `[Unreleased]` section, bumps the version, writes the compare links and tags `vX.Y.Z`. A `commit-msg` hook refuses a commit that references an issue and changes shipped code without a `CHANGELOG.md` line, so entries stop going missing

### Changed

- `STRIPE_SECRET_KEY` should hold a restricted key scoped to write on Checkout Sessions and read on Tax, not a full secret key. The variable name is unchanged; only the value and the guidance around it are

### Fixed

- Admin: shrinking a run left the numbers above the new size in the database, so a run taken from 50 down to 20 reported "50 of 20 left" ever after. Shrinking now removes those numbers — unless one of them is held in a checkout that is still open, in which case the save is refused and names the number, rather than deleting a number somebody is part-way through buying ([#36](https://github.com/vanyanv/chrisneddys-site/issues/36))
- Admin: resetting a password from the emailed link only changed the password — anyone still signed in on another device stayed signed in, which defeats the point of resetting a password because you think someone got in. A reset now signs out every device, the same way changing your password from Settings already does ([#36](https://github.com/vanyanv/chrisneddys-site/issues/36))
- Admin: an owner who mistyped their password five times was locked out for 15 minutes — and every retry while locked counted as another failure, restarting that 15-minute window, so they could never get back in. Getting locked out no longer records a new failure, and a correct password now clears that owner's earlier mistakes ([#34](https://github.com/vanyanv/chrisneddys-site/issues/34))
- Checkout Sessions declared no product tax code and no tax behaviour, so both fell back to the Stripe account's presets. That account carries none of either, and clothing is taxed differently from the general default in several states. Line items now declare `txcd_30011000` and the shipping rate `txcd_92010001`, both tax-exclusive
- `DEPLOY.md` claimed Stripe errors at session-creation time when Tax has no registration, so checkout would break rather than under-charge. It is the other way round: an activated Stripe Tax with no registration in the buyer's jurisdiction collects zero, returns no error and looks entirely normal. Before that, with no head office address set, Tax is not active at all and a calculation is rejected outright. Both states are now written down
- Admin: the entire `/admin` interface rendered unstyled — correct typography on a blank white page. `admin.css` draws with 11 `--a-*` tokens that were defined only in `counter.css`, which the admin route group never loads, so every `background`, `border`, `box-shadow` and `color` in it was dropped as invalid at computed-value time. The tokens now live in `src/styles/tokens.css`, imported by both stylesheets
- Admin: photos seeded from the repo showed as black squares in the product editor and the products table. Those rows store a stem (`front`, `angle`) resolved against the product's `photoDir`, which the admin had no field for and no code path to use — it understood only uploaded Blob URLs. Both now resolve through one helper, the way the storefront always has
- Admin: the product slug field accepted any value. Its `pattern` was `^[a-z0-9-]+$`, which fails to compile under the `v` flag browsers apply to that attribute, so the invalid regex was discarded along with the validation
- Admin: the sidebar painted a stray horizontal scrollbar under the last nav item once it became a column at 900px and up
- Bag: a line named only the second half of the product's display name — "— BLUE" rather than "THE FOAM TRUCKER — BLUE"
- Development: `next dev` no longer serves a Content-Security-Policy that breaks itself. `upgrade-insecure-requests` rewrote the admin's own upload request to https against a port speaking no TLS, and the absence of `'unsafe-eval'` blocked react-refresh, so no client component on the site hydrated — add-to-bag, the bag drawer and the product gallery all silently did nothing. Both are now gated on `NODE_ENV`; the deployed policy is unchanged
- `pnpm install` failed before it could start: the lockfile carried two concatenated YAML documents, and `packageManager` pinned a pnpm version that does not exist

## [0.2.0] - 2026-09-13

### Changed
